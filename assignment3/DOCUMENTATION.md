## `data/documents.json`

**Generated by:** `scripts/build_documents.py`  
**Size:** 206 documents, ~198 KB

This is the single content database for all search. Each document is a JSON object:

```json
{
  "id": "yes-016",
  "type": "yes-unit",
  "title": "Engineering Earthquake-Resistant Buildings",
  "category": "YES - YES Middle School (Grades 6–8)",
  "text": "Engineering Earthquake-Resistant Buildings is a YES Middle School unit ...",
  "url": "https://yes.mos.org/curricula/yes-middle-school/engineering-earthquake-resistant-buildings"
}
```

| Field | Purpose |
|---|---|
| `id` | Unique identifier, prefixed by type (`yes-`, `exh-`, `ste-`, `doc-`) |
| `type` | `yes-unit`, `yes-overview`, `exhibit`, `ste-standard`, `ste-overview`, `research-document` |
| `title` | Display name shown in search results |
| `category` | Sub-grouping shown in results (e.g. "YES - YES Middle School (Grades 6–8)") |
| `text` | The text that gets embedded and searched. Combines title, description, aligned standards and related exhibits |
| `url` | The real page on `yes.mos.org`, `mos.org`, `doe.mass.edu`, or the source PDF |

**Document counts by type:**

| Type | Count | Source |
|---|---|---|
| `yes-unit` | 53 | YES unit pages on `yes.mos.org`, including career explorations and CS modules |
| `yes-overview` | 7 | One per YES section (preschool, elementary, middle, enrichment, etc.) |
| `exhibit` | 26 | MOS exhibit pages from `mos.org/visit/exhibits/` |
| `ste-standard` | 20 | Massachusetts STE standards from the alignment table |
| `ste-overview` | 1 | Overall MA STE framework objectives |
| `research-document` | 99 | Curated STEM PDFs from NASA, USGS, FEMA, NPS, EPA, Code.org, CS Unplugged, etc. |

**Why `text` is composite:** a vector search works by semantic similarity to the embedded `text` field. By composing text that includes the unit description, its aligned MA STE standard, and related exhibits, a single query like "light and optics" can surface a YES unit, its matching standard, and a museum exhibit in one search, with no separate queries.

## `data/index.json`

**Generated by:** `scripts/buildIndex.js` (Node.js)  
**Size:** ~2.4 MB  
**Gitignored** — rebuild on each machine with `npm run build-index`

Each entry in `index.json` is the same object as `documents.json` plus an `embedding` array:

```json
{
  "id": "yes-016",
  "title": "Engineering Earthquake-Resistant Buildings",
  ...
  "embedding": [0.032, -0.041, 0.018, ...]   ← 384 numbers, L2-normalised
}
```

The 384-number vector is produced by the `Xenova/all-MiniLM-L6-v2` model, a compact sentence-transformer that maps any text to a fixed-size point in 384-dimensional space. Documents with similar meaning end up close together in that space. At search time, the query is mapped to the same space and the closest documents (by cosine similarity = dot product of unit vectors) are returned.

## `scripts/build_documents.py`

**Language:** Python 3  
**Dependencies:** `openpyxl`, `requests`, `beautifulsoup4`  
**Run:** `python3 scripts/build_documents.py`

Reads four source markdown files and the IA spreadsheet and writes `data/documents.json`. It does **not** need network access (all network fetching is done by the two `fetch_` scripts).

### Key sections

**`parse_yes()`** — reads `Youth Engineering Solutions (YES) Curricula List.md` section by section. Each `##` heading becomes a YES section (Preschool, Elementary, etc.); bullet points and table rows become unit names and grade bands.

**`table_rows(path)`** — parses a markdown table into a list of row arrays, stripping markdown link syntax (`[text](url)` → `text`) so the content is clean plain text.

**`xlsx_categories()`** — opens `Information_Architecture_MOS_Ed_portal.xlsx` with openpyxl and reads the hyperlink targets. The spreadsheet's cell hyperlinks are the definitive list of 100 curated research document URLs. Each URL is mapped to its Level 4 category (e.g. "Computer Science, AI, Robotics").

**`norm(name)`** — normalises a unit name to a lookup key by lowercasing, removing parenthetical content, and dropping common stop words like "engineering" and "yes". Used to match a unit name in the YES list against entries in the exhibit and standards alignment tables.

**`matches(unit_norm, names)`** — checks whether a normalised unit name appears in a list of normalised activity names extracted from the exhibit or standards table. Used to cross-link: "this exhibit matched this YES unit" and "this YES unit aligns with this standard".

**Main loop — YES units:** For each unit, `text` is built from:
1. The unit name and section (e.g. "Engineering Earthquake-Resistant Buildings is a YES Middle School unit from the Museum of Science, Boston.")
2. The official description fetched from `yes.mos.org` (from `site_pages.json`)
3. The grade band if available
4. Any matching MA STE standard with its description
5. Any related museum exhibit names

**Main loop — exhibits:** For each exhibit row from the alignment table, `text` is built from the alignment rationale, the official MOS description (from `site_pages.json`), whether it is a curriculum gap, and the primary MA STE standard code.

**Main loop — research documents:** Uses `link_replacements.json` to substitute working URLs for the 78 dead links found in the original spreadsheet, and `pdf_extracts.json` to include the opening text of each document so the search can match against actual content.

## `scripts/fetch_extracts.py`

**Language:** Python 3  
**Dependencies:** `openpyxl`, `requests`, `beautifulsoup4`, `pdftotext` (system)  
**Run:** `python3 scripts/fetch_extracts.py`  
**Output:** `data/sources/pdf_extracts.json`

Downloads each linked document from the IA spreadsheet (using working replacements from `link_replacements.json` where the original is dead) and extracts the opening text:
- For PDFs: pipes the file through `pdftotext -l 3` (first 3 pages only) for speed.
- For HTML pages: strips navigation and script tags with BeautifulSoup and extracts body text.
- Uses two User-Agent strings in sequence (browser UA, then `curl/8.7.1`) because some government servers block one or the other.
- Saves up to 1,500 characters of text per document. `build_documents.py` includes the first 700 of those in the `text` field.

## `scripts/fetch_site_pages.py`

**Language:** Python 3  
**Dependencies:** `requests`, `beautifulsoup4`  
**Run:** `python3 scripts/fetch_site_pages.py`  
**Output:** `data/sources/site_pages.json`

Fetches every page listed in `data/sources/site_links.json` — the real `yes.mos.org` unit pages, `mos.org` exhibit pages, and the DESE standards page. For each page it saves:
- `title` — from the `og:title` meta tag or `<title>` element
- `description` — from the `name="description"` meta tag (the official one-line summary)
- `body` — up to 1,500 characters of main-content text (with nav/footer/script stripped)

`build_documents.py` uses `description` to populate each YES unit's and exhibit's `text` field with the museum's own words.

## `scripts/buildIndex.js`

**Language:** Node.js (ES module)  
**Dependencies:** `@xenova/transformers`  
**Run:** `npm run build-index`  
**Source:** copied from `467-vectorsearch-demo/scripts/buildIndex.js`

```js
// For each document in documents.json:
const embedding = await embedText(`${doc.title}. ${doc.text}`);
// embedText() returns a 384-element Float32 array, L2-normalised
indexed.push({ ...doc, embedding });
```

The document title is prepended to the text before embedding. This is a standard trick: it gives the title extra weight in the semantic representation, so a query mentioning the exact unit name gets a strong hit even if it uses different vocabulary in the body.

The model (`Xenova/all-MiniLM-L6-v2`) is a 23 MB ONNX-quantised version of the `all-MiniLM-L6-v2` sentence transformer. It produces identical vectors whether run in Node.js or in the browser via the same `@xenova/transformers` library, confirmed by the test harness (similarity 1.0000).

## `src/embeddings.js`

**Language:** Node.js / browser ES module (same file works in both)  
**Source:** copied from `467-vectorsearch-demo/src/embeddings.js`

```js
export async function embedText(text) {
  const embedder = await getEmbedder();           // lazy-loads the model once
  const output = await embedder(text, {
    pooling: "mean",     // average token vectors → single document vector
    normalize: true      // L2-normalise → dot product = cosine similarity
  });
  return Array.from(output.data);
}

export function cosineSimilarity(a, b) {
  let dot = 0;
  for (let i = 0; i < a.length; i++) dot += a[i] * b[i];
  return dot;            // both vectors are already unit-length, so dot = cosine
}
```

Mean pooling averages the per-token vectors into one vector representing the whole sentence. L2 normalisation scales the vector to unit length, which turns cosine similarity (normally `dot(a,b) / (|a| × |b|)`) into a plain dot product — cheaper to compute, especially in PHP and at 206 × 384 multiplications.

## `public/ask.php`

**Language:** PHP 8.4  
**Deployed to:** `public_html/ask.php` on `web.simmons.edu`  
**API key:** `/users/c/colek/.anthropic_key` (permissions 604; never in git or `public_html`)

This is the RAG (Retrieval-Augmented Generation) endpoint. It:
1. Receives a POST request with `{"query": "...", "persona": "educators"|"students"|"parents"}`.
2. Loads `index.json` from `public_html/data/index.json`.
3. Filters documents by persona.
4. Scores every matching document by keyword overlap with the query.
5. Passes the top 6 to Claude Haiku with a grounded system prompt.
6. Returns `{answer, persona, results[]}` as JSON.

### Section by section

**Persona filtering:**
```php
const PERSONA_TYPES = [
    'students'  => ['exhibit', 'yes-unit', 'yes-overview'],
    'parents'   => ['exhibit'],
    'educators' => null,   // null = all types (206 docs)
];
```
Educators see everything. Students see exhibits and YES units. Parents see exhibits only. This matches the three radio buttons on the wireframe's "Ask LLM" panel.

**Keyword retrieval:**
```php
$terms = array_filter(preg_split('/\W+/u', strtolower($query)));
foreach ($docs as $doc) {
    $hay  = strtolower($doc['title'] . ' ' . $doc['category'] . ' ' . $doc['text']);
    $hits = 0;
    foreach ($terms as $t) {
        if (strlen($t) > 2 && str_contains($hay, $t)) $hits++;
    }
    $scored[] = ['doc' => $doc, 'score' => $hits / count($terms)];
}
```
PHP can't run the MiniLM model (which requires ONNX/WebAssembly), so it falls back to term frequency. The score is the fraction of query words (longer than 2 characters) that appear in the document. A future improvement would have the browser do vector ranking and send the top IDs to PHP, which then only needs to call the LLM.

**System prompt:**
```
You are a helpful assistant for the Museum of Science, Boston educator portal.
Answer in 2-4 sentences, citing only the provided resources by their title.
End with a one-sentence suggestion for how to explore further on the portal.
Do not invent resources not listed below.
```
The "do not invent" instruction is the grounding constraint — it prevents the model from hallucinating resources that don't exist in the index.

**Claude Haiku call:**
```php
$payload = json_encode([
    'model'      => 'claude-haiku-4-5-20251001',
    'max_tokens' => 350,
    'system'     => $system,
    'messages'   => [['role' => 'user', 'content' => $user_msg]],
]);
```
350 tokens is enough for 2-4 tight sentences. Claude Haiku is chosen for speed (sub-second) and cost (~$0.0003 per call at this token count).

**Graceful degradation:** if the API call fails (network error, rate limit, etc.), `ask.php` still returns the keyword search results with a note in the `answer` field. The page is never broken by an LLM failure.

## `data/sources/link_replacements.json`

78 of the 100 research document URLs in the original IA spreadsheet returned 404 or 403. Six parallel background agents searched for working replacements, each handling 13 documents. Every proposed URL was independently verified with `curl` (HTTP 200, correct content type, topic confirmed). The replacements are stored here so `build_documents.py` can use them without re-fetching.

Notable findings:
- Most NASA PDFs at the old `nasa.gov/wp-content/uploads` paths have moved. New paths are at `assets.science.nasa.gov`.
- All FEMA PDFs now return 403 with a browser User-Agent but 200 with `curl/8.7.1`.
- Code.org lesson plans are served as `application/octet-stream` but are valid PDFs.
- CS Unplugged PDFs are available but at different paths than the originals.
- 6 items have no replacement PDF and are represented by HTML resource pages instead.
- 1 document (USGS Earthquakes Student Information Pamphlet) had no working replacement and was removed from the index.
