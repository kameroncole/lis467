## `data/documents.json`

**Generated by:** `scripts/build_documents.py`  
**Size:** 206 documents, ~198 KB

This is the single content database for all search. Each document is a JSON object:

```json
{
  "id": "yes-016",
  "type": "yes-unit",
  "title": "Engineering Earthquake-Resistant Buildings",
  "category": "YES - YES Middle School (Grades 6–8)",
  "text": "Engineering Earthquake-Resistant Buildings is a YES Middle School unit ...",
  "url": "https://yes.mos.org/curricula/yes-middle-school/engineering-earthquake-resistant-buildings"
}
```

| Field | Purpose |
|---|---|
| `id` | Unique identifier, prefixed by type (`yes-`, `exh-`, `ste-`, `doc-`) |
| `type` | `yes-unit`, `yes-overview`, `exhibit`, `ste-standard`, `ste-overview`, `research-document` |
| `title` | Display name shown in search results |
| `category` | Sub-grouping shown in results (e.g. "YES - YES Middle School (Grades 6–8)") |
| `text` | The text that gets embedded and searched. Combines title, description, aligned standards and related exhibits |
| `url` | The real page on `yes.mos.org`, `mos.org`, `doe.mass.edu`, or the source PDF |

**Document counts by type:**

| Type | Count | Source |
|---|---|---|
| `yes-unit` | 53 | YES unit pages on `yes.mos.org`, including career explorations and CS modules |
| `yes-overview` | 7 | One per YES section (preschool, elementary, middle, enrichment, etc.) |
| `exhibit` | 26 | MOS exhibit pages from `mos.org/visit/exhibits/` |
| `ste-standard` | 20 | Massachusetts STE standards from the alignment table |
| `ste-overview` | 1 | Overall MA STE framework objectives |
| `research-document` | 99 | Curated STEM PDFs from NASA, USGS, FEMA, NPS, EPA, Code.org, CS Unplugged, etc. |

**Why `text` is composite:** a vector search works by semantic similarity to the embedded `text` field. By composing text that includes the unit description, its aligned MA STE standard, and related exhibits, a single query like "light and optics" can surface a YES unit, its matching standard, and a museum exhibit in one search, with no separate queries.

## `data/index.json`

**Generated by:** `scripts/buildIndex.js` (Node.js)  
**Size:** ~2.4 MB  
**Gitignored** — rebuild on each machine with `npm run build-index`

Each entry in `index.json` is the same object as `documents.json` plus an `embedding` array:

```json
{
  "id": "yes-016",
  "title": "Engineering Earthquake-Resistant Buildings",
  ...
  "embedding": [0.032, -0.041, 0.018, ...]   ← 384 numbers, L2-normalised
}
```

The 384-number vector is produced by the `Xenova/all-MiniLM-L6-v2` model, a compact sentence-transformer that maps any text to a fixed-size point in 384-dimensional space. Documents with similar meaning end up close together in that space. At search time, the query is mapped to the same space and the closest documents (by cosine similarity = dot product of unit vectors) are returned.

## `scripts/build_documents.py`

**Language:** Python 3  
**Dependencies:** `openpyxl`, `requests`, `beautifulsoup4`  
**Run:** `python3 scripts/build_documents.py`

Reads four source markdown files and the IA spreadsheet and writes `data/documents.json`. It does **not** need network access (all network fetching is done by the two `fetch_` scripts).

### Key sections

**`parse_yes()`** — reads `Youth Engineering Solutions (YES) Curricula List.md` section by section. Each `##` heading becomes a YES section (Preschool, Elementary, etc.); bullet points and table rows become unit names and grade bands.

**`table_rows(path)`** — parses a markdown table into a list of row arrays, stripping markdown link syntax (`[text](url)` → `text`) so the content is clean plain text.

**`xlsx_categories()`** — opens `Information_Architecture_MOS_Ed_portal.xlsx` with openpyxl and reads the hyperlink targets. The spreadsheet's cell hyperlinks are the definitive list of 100 curated research document URLs. Each URL is mapped to its Level 4 category (e.g. "Computer Science, AI, Robotics").

**`norm(name)`** — normalises a unit name to a lookup key by lowercasing, removing parenthetical content, and dropping common stop words like "engineering" and "yes". Used to match a unit name in the YES list against entries in the exhibit and standards alignment tables.

**`matches(unit_norm, names)`** — checks whether a normalised unit name appears in a list of normalised activity names extracted from the exhibit or standards table. Used to cross-link: "this exhibit matched this YES unit" and "this YES unit aligns with this standard".

**Main loop — YES units:** For each unit, `text` is built from:
1. The unit name and section (e.g. "Engineering Earthquake-Resistant Buildings is a YES Middle School unit from the Museum of Science, Boston.")
2. The official description fetched from `yes.mos.org` (from `site_pages.json`)
3. The grade band if available
4. Any matching MA STE standard with its description
5. Any related museum exhibit names

**Main loop — exhibits:** For each exhibit row from the alignment table, `text` is built from the alignment rationale, the official MOS description (from `site_pages.json`), whether it is a curriculum gap, and the primary MA STE standard code.

**Main loop — research documents:** Uses `link_replacements.json` to substitute working URLs for the 78 dead links found in the original spreadsheet, and `pdf_extracts.json` to include the opening text of each document so the search can match against actual content.

## `scripts/buildIndex.js`

**Language:** Node.js (ES module)  
**Dependencies:** `@xenova/transformers`  
**Run:** `npm run build-index`  
**Source:** copied from `467-vectorsearch-demo/scripts/buildIndex.js`

```js
// For each document in documents.json:
const embedding = await embedText(`${doc.title}. ${doc.text}`);
// embedText() returns a 384-element Float32 array, L2-normalised
indexed.push({ ...doc, embedding });
```

The document title is prepended to the text before embedding. This is a standard trick: it gives the title extra weight in the semantic representation, so a query mentioning the exact unit name gets a strong hit even if it uses different vocabulary in the body.

The model (`Xenova/all-MiniLM-L6-v2`) is a 23 MB ONNX-quantised version of the `all-MiniLM-L6-v2` sentence transformer. It produces identical vectors whether run in Node.js or in the browser via the same `@xenova/transformers` library, confirmed by the test harness (similarity 1.0000).

## `src/embeddings.js`

**Language:** Node.js / browser ES module (same file works in both)  
**Source:** copied from `467-vectorsearch-demo/src/embeddings.js`

```js
export async function embedText(text) {
  const embedder = await getEmbedder();           // lazy-loads the model once
  const output = await embedder(text, {
    pooling: "mean",     // average token vectors → single document vector
    normalize: true      // L2-normalise → dot product = cosine similarity
  });
  return Array.from(output.data);
}

export function cosineSimilarity(a, b) {
  let dot = 0;
  for (let i = 0; i < a.length; i++) dot += a[i] * b[i];
  return dot;            // both vectors are already unit-length, so dot = cosine
}
```

Mean pooling averages the per-token vectors into one vector representing the whole sentence. L2 normalisation scales the vector to unit length, which turns cosine similarity (normally `dot(a,b) / (|a| × |b|)`) into a plain dot product — cheaper to compute, especially in PHP and at 206 × 384 multiplications.

## `public/ask.php`

**Language:** PHP 8.4  
**Deployed to:** `public_html/ask.php` on `web.simmons.edu`  
**API key:** `/users/c/colek/.anthropic_key` (permissions 604; never in git or `public_html`)

This is the RAG (Retrieval-Augmented Generation) endpoint. It:
1. Receives a POST request with `{"query": "...", "persona": "educators"|"students"|"parents"}`.
2. Loads `index.json` from `public_html/data/index.json`.
3. Filters documents by persona.
4. Scores every matching document by keyword overlap with the query.
5. Passes the top 6 to Claude Haiku with a grounded system prompt.
6. Returns `{answer, persona, results[]}` as JSON.

### Section by section

**Persona filtering:**
```php
const PERSONA_TYPES = [
    'students'  => ['exhibit', 'yes-unit', 'yes-overview'],
    'parents'   => ['exhibit'],
    'educators' => null,   // null = all types (206 docs)
];
```
Educators see everything. Students see exhibits and YES units. Parents see exhibits only. This matches the three radio buttons on the wireframe's "Ask LLM" panel.

**Keyword retrieval:**
```php
$terms = array_filter(preg_split('/\W+/u', strtolower($query)));
foreach ($docs as $doc) {
    $hay  = strtolower($doc['title'] . ' ' . $doc['category'] . ' ' . $doc['text']);
    $hits = 0;
    foreach ($terms as $t) {
        if (strlen($t) > 2 && str_contains($hay, $t)) $hits++;
    }
    $scored[] = ['doc' => $doc, 'score' => $hits / count($terms)];
}
```
PHP can't run the MiniLM model (which requires ONNX/WebAssembly), so it falls back to term frequency. The score is the fraction of query words (longer than 2 characters) that appear in the document. A future improvement would have the browser do vector ranking and send the top IDs to PHP, which then only needs to call the LLM.

**System prompt:**
```
You are a helpful assistant for the Museum of Science, Boston educator portal.
Answer in 2-4 sentences, citing only the provided resources by their title.
End with a one-sentence suggestion for how to explore further on the portal.
Do not invent resources not listed below.
```
The "do not invent" instruction is the grounding constraint — it prevents the model from hallucinating resources that don't exist in the index.

**Claude Haiku call:**
```php
$payload = json_encode([
    'model'      => 'claude-haiku-4-5-20251001',
    'max_tokens' => 350,
    'system'     => $system,
    'messages'   => [['role' => 'user', 'content' => $user_msg]],
]);
```
350 tokens is enough for 2-4 tight sentences. Claude Haiku is chosen for speed (sub-second) and cost (~$0.0003 per call at this token count).

**Graceful degradation:** if the API call fails (network error, rate limit, etc.), `ask.php` still returns the keyword search results with a note in the `answer` field. The page is never broken by an LLM failure.

## `scripts/build_nav.py`

**Input:** `assignment3/Information_Architecture_MOS_Ed_portal.xlsx`
**Output:** the navigation block inside `public/index.html` and `public/search-results.html`
**Requires:** `pip install openpyxl` (Python 3.10+, otherwise standard library only)

The spreadsheet is the single source of truth for the site navigation. The script reads it, builds a tree, renders the tree as nested `<ul>` menus, and writes the result into both pages. Nothing is hand-edited in the pages' nav.

```bash
cd assignment3/webserver/scripts
python3 build_nav.py                                  # update both pages (depth 4)
python3 build_nav.py --depth 3                        # persona > main nav > dropdown only
python3 build_nav.py --dry-run                        # print the HTML, change nothing
python3 build_nav.py --xlsx IA.xlsx --pages ../public/index.html
```

| Flag | Default | Meaning |
|---|---|---|
| `--xlsx` | `assignment3/Information_Architecture_MOS_Ed_portal.xlsx` | Spreadsheet to read |
| `--pages` | `public/index.html` and `public/search-results.html` | Pages to update (one or more) |
| `--depth` | `4` | Levels to show: 2 = persona and main nav, 3 = plus dropdown, 4 = plus category or link, 5 = everything |
| `--dry-run` | off | Print the nav HTML instead of writing files |

### The spreadsheet it expects

One sheet. A header row whose first cell starts with `Level 1`, then one row per nav entry:

| Level 1 (Persona Nav) | Level 2 (Main Nav) | Level 3 (dropdown) | Level 4 (Category/Direct Link) | Level 5 (Direct Link) | URL Path | Page Purpose |
|---|---|---|---|---|---|---|
| Educators | Youth Engineering Solutions | Preschool | Wind-Powered Fans | | /yes/preschool/wind-fans | |

Columns A–E hold the path through the menu (a row stops at its first empty level) and column F holds the URL. Rows above the header (Global Utilities and Dashboard) are skipped, since those are the search box, chat and logo link rather than menu items. Rows whose Level 1 is not one of the four personas are ignored.

### Code walkthrough

**Constants.**
- `PERSONA_ORDER` is `["Students", "Parents", "Educators", "About"]`, the left-to-right order in the wireframe. The sheet lists Educators first, so the script ignores sheet order for the top bar.
- `PERSONA_LABELS` turns the sheet's bare names into the wireframe labels "For Students", "For Parents" and "For Educators". "About" is left alone.
- `LOGO_HTML` is the logo link (`images/logo.png`, back to `index.html`), the first item in the bar.
- `START` and `END` are the `<!-- NAV:START -->` and `<!-- NAV:END -->` markers.

**`Node`** is one menu entry: a `label`, a `children` dict keyed by label, and a list of `urls`.
- `child(label)` returns the existing child with that label or creates it. This is how rows that share a prefix (every row starting `Educators > Youth Engineering Solutions > Preschool`) merge into one branch.
- `href` decides the link target. If the node has exactly one distinct URL and no children, it links there. Otherwise (a category that holds other items, or a node with no URL) it returns `#`.

**`clean(value)`** turns a cell into a stripped string, or `None` if it is empty, so blanks and whitespace cells behave the same.

**`read_tree(xlsx_path)`** opens the workbook with openpyxl and finds the header row (first cell starts with `Level 1`; exits with a message if there is none). For each row below it:
1. Take columns A–E as the path, and column F as the URL.
2. Skip the row if Level 1 is not a known persona.
3. Walk from the root, calling `child()` for each non-empty level and stopping at the first empty one.
4. Append the URL to the node where the walk ended.

It returns the root `Node`.

**`make_href(url)`** leaves `http(s)` and `#` links alone and strips the leading `/` from internal paths, so `/exhibits/#` becomes `exhibits/#`. This keeps links relative so they resolve under `~colek/` on the Simmons server.

**`render_item(node, depth, max_depth)`** renders one `<li>`. External links get `target="_blank" rel="noopener"`. If the node has children and `depth < max_depth`, the `<li>` gets class `has-sub` and a nested list from `render_list`. Labels and URLs are passed through `html.escape`.

**`render_list(nodes, depth, max_depth)`** renders a `<ul class="sub">`. If every item in it is a leaf (such as the 26 exhibits), it also gets `menu-scroll` so the CSS can cap its height and scroll. Lists that contain flyouts must not scroll, because `overflow` would clip the flyouts.

**`render_nav(root, max_depth)`** builds the whole bar. For each persona in `PERSONA_ORDER` it:
- collapses a same-named leaf child (`About > About`) into the persona link itself, so "About" links straight to `/about`;
- applies `PERSONA_LABELS` to the visible text;
- adds a dropdown from `render_list` when the persona has children and `max_depth > 1`.

It returns the logo plus the persona list wrapped in `<nav class="site-nav">`, with the markers included.

**`inject(page, nav_html)`** reads a page, replaces everything from `START` to `END` with the new markup (a regex with `re.S`, using a lambda replacement so backslashes in the HTML are not treated as escapes), and writes it back. A page without both markers makes the script exit with an error rather than guess where the nav goes.

**`main()`** parses the flags, builds the tree, renders it, and either prints it (`--dry-run`) or injects it into each page. Running it twice produces identical files.

### Generated markup

```html
<!-- NAV:START -->
<nav class="site-nav" aria-label="Main">
<a class="logo" href="index.html"><img src="images/logo.png" alt="ACI Inc. logo - back to dashboard"></a>
<ul class="nav-list">
<li class="has-sub"><a href="#">For Educators</a><ul class="sub">
<li class="has-sub"><a href="#">Exhibits</a><ul class="sub menu-scroll">
<li><a href="exhibits/#">Gaia Globe</a></li>
...
</ul></li>
...
</ul></li>
</ul>
</nav>
<!-- NAV:END -->
```

The classes are styled in `public/css/layout.css`: `.site-nav` is the bar, `.nav-list` the top-level items, `.sub` the dropdown panels (hidden until hover or keyboard focus), `.has-sub` marks items with a ▸ flyout, and `.menu-scroll` limits long lists to 70% of the viewport height.

### Known limits

- Many nav targets are still placeholders (`#` or `exhibits/#`) because those pages do not exist yet.
- Level 5 is hidden by default: it is mostly 100 PDF links under Resources, which would make an unusable menu.
- If the sheet gains a fifth persona, add it to `PERSONA_ORDER` (and `PERSONA_LABELS` if it needs a "For ..." label), or its rows are ignored.
- After changing the spreadsheet, re-run the script and redeploy both HTML files.

### `index.html` (Dashboard / Home Page)

`<main>` has four sections, top to bottom:

1. **Hero** (`section.hero`). `.hero` gives a `--gray-light` background with centered text. The `h1` "Museum of Science" is sized in `.hero h1` and picks up Cascadia Code and `--blue-dark` from `colors.css`. Below it is a "Featured Exhibit" link styled `.btn.btn-dark`.
2. **Ask LLM** (`section.ask-llm`). Described above. Radio options are Students, Parents and Educators, with none selected, as drawn in the wireframe.
3. **Upcoming Exhibits** (`section.exhibits`).
   - `.exhibits` centers the heading and adds padding.
   - `div.carousel` is a horizontal flex row with `overflow-x: auto` and `scroll-snap-type: x mandatory`, so cards scroll sideways and snap into place. It uses native scrolling; there are no arrow buttons yet.
   - It contains 26 `figure.card` elements, one per `exhibit` in `documents.json`, in the same order. Each card is `flex: 0 0 min(300px, 70%)` wide with `scroll-snap-align: start`.
   - 18 cards have a photo from `images/exhibits/`: an `img` (16:9, `object-fit: cover`, `loading="lazy"`), a `figcaption` with the exhibit name (`.card figcaption`), and a `small.credit` line.

   - `.calendar` is a 280 px column. Its `h3` "Calendar Widget" is a `--purple-dark` bar. `.calendar-grid` is a 6-column CSS grid of 30 `--gray-light` squares (`span`), a placeholder for a real calendar.
   - `.event-info` holds the "Event Info" `h2`, placeholder text, and a "Learn More" `.btn`.

### `search-results.html` (Educator Search Result Page)

`<main class="results-layout">` is a two-column CSS grid (`3fr 2fr`) that collapses to one column at 800 px or narrower.

**Left column** (`div.results-main`, a vertical flex stack):

- `section.query`: a bold "Search Results" label (`.query .label`), the "Query Restated" `h1` (`.query h1`), and a paragraph of placeholder LLM output. This is where the user's restated question and the LLM summary will go.

**Right column** (`aside.results-side`, a vertical flex stack):

Each row is a flex row with a `.icon` (a 48 × 56 px white box with a `--blue-dark` border and the text "PDF", standing in for the document icon) and a text block with the document title (`h3`) and a one-line summary (`p`).

## Rebuild instructions (for the Linux machine)

After `git pull`:

```bash
cd assignment3/webserver

# 1. Install Node dependencies (first time or after package.json changes)
npm ci

# 2. Build the vector index (needs network the first time to download the model)
npm run build-index
# → writes data/index.json (~2.4 MB)

# 3. (Optional) Re-fetch PDF extracts if source links change
python3 scripts/fetch_extracts.py
# → updates data/sources/pdf_extracts.json

# 4. (Optional) Re-fetch official site descriptions if mos.org/yes.mos.org pages change
python3 scripts/fetch_site_pages.py
# → updates data/sources/site_pages.json

# 5. (Optional) Regenerate documents.json from updated sources
python3 scripts/build_documents.py
# → updates data/documents.json
# → then re-run npm run build-index to update the vector index

# 6. (Optional) Regenerate the site navigation after editing the IA spreadsheet
python3 -m pip install openpyxl
python3 scripts/build_nav.py
# → rewrites the NAV block in public/index.html and public/search-results.html
```

`data/index.json` is gitignored. Always run `npm run build-index` after pulling.
